📊 多層反饋佇列（Multilevel Feedback Queue）2011/12/13 必考
考試標準設定 + 規則

Q2 最高：RR q=4ms（新行程/I/O 完成進此層）→ Q1：RR q=6ms → Q0：FCFS

  • 高層行程搶占低層行程
  • 用完 quantum 或被搶占 → 降一層
  • I/O 完成回來當作新到達 → 進 Q2（會搶占低層）

🖥️ 多處理器排程
  • Asymmetric：master 處理所有排程；SMP：各自排程（主流）
  • Processor affinity：行程留在同處理器保 cache（soft/hard）
  • 負載平衡：Push migration（kernel 推）+ Pull migration（閒置處理器拉）
  • 注意：load balancing 與 affinity 互相抵觸
📐 演算法評估 & Little's Formula

Little's formula：n = λ × W（佇列長 = 到達率 × 等待時間）

  • Deterministic modeling：確切數字、僅適用該案例
  • Queueing models：用 Little's formula（分布常不切實際→結果存疑）
  • Simulations：trace tape，較準但昂貴
🔵 Chapter 6 — Synchronization
🚦 臨界區三需求 + Race Condition

Race condition：多行程同時存取共享資料，結果取決於存取順序（如 counter++ 與 counter-- 並行可能得 4/5/6）。

Mutual Exclusion
同時只有一個行程在臨界區
Progress
沒人在臨界區時，想進的能在有限時間決定誰進
Bounded Waiting
提出請求後，他人進入次數有上限
🔐 Peterson's Solution 2012 考
do { flag[i] = TRUE; // 我想進入 turn = j; // 先讓你 while (flag[j] && turn == j); // 你想進且輪到你→等 // CRITICAL SECTION flag[i] = FALSE; // 離開 // REMAINDER SECTION } while (TRUE);
⚙️ 同步硬體 TestAndSet（n-process）2011 考
boolean TestAndSet(boolean *target){ boolean rv=*target; *target=TRUE; return rv; } // shared: lock, waiting[n] = false do { waiting[i] = TRUE; key = TRUE; while (waiting[i] && key) key = TestAndSet(&lock); waiting[i] = FALSE; // CRITICAL SECTION j = (i+1) % n; while ((j!=i) && !waiting[j]) j = (j+1) % n; if (j == i) lock = FALSE; else waiting[j] = FALSE; // REMAINDER SECTION } while (TRUE);

Atomic = 不可中斷。簡單版 TestAndSet 滿足互斥但不滿足 bounded waiting，故需 waiting[] 陣列版。

🚥 Semaphore（號誌）
wait(S){ while(S<=0); S--; } signal(S){ S++; }
  • Binary semaphore = mutex（0/1）
  • Counting semaphore = 資源數
  • wait/signal 必須原子！
號誌的三大問題
  • Deadlock：互等對方號誌
  • Starvation：LIFO 順序
  • Busy waiting (spinlock)：浪費 CPU（多處理器短鎖有用）
🍽️ Bounded-Buffer（生產者-消費者）2013 考
// mutex=1, empty=n, full=0 // Producer wait(empty); wait(mutex); // 放入 buffer signal(mutex); signal(full); // Consumer wait(full); wait(mutex); // 取出 buffer signal(mutex); signal(empty);

先 wait(empty/full)，再 wait(mutex)，順序顛倒會死結！

📖 Readers-Writers（第一類）2012/2016 考
// mutex=1, wrt=1, readcount=0 // Reader wait(mutex); readcount++; if(readcount==1) wait(wrt); signal(mutex); // reading wait(mutex); readcount--; if(readcount==0) signal(wrt); signal(mutex); // Writer wait(wrt); /*write*/ signal(wrt);
🍴 Dining Philosophers & Monitor

哲學家用餐：5 人 5 筷，需左右兩支才能吃。直接用 semaphore 會死結（全拿左筷）。

解法：①最多 4 人上桌 ②兩支都可用才拿 ③奇偶先拿不同邊。
無死結 ≠ 無飢餓

Monitor：同時只有一個行程活躍。Condition variable：x.wait()/x.signal()。

  • Signal and wait：喚醒者先跑
  • Signal and continue：發訊號者繼續
  • 對比 semaphore：monitor 的 signal 無人等待時無效
🟠 Chapter 7 — Deadlocks
⛓️ 死結的四個必要條件（同時成立才死結）2012/14/15 考
1. Mutual Exclusion
資源一次只能一個行程用
2. Hold and Wait
持有資源又等其他資源
3. No Preemption
資源只能自願釋放
4. Circular Wait
行程形成等待環
📈 資源配置圖（RAG）
  • Request edge Pi→Rj；Assignment edge Rj→Pi
  • 無環 → 一定無死結
  • 有環 + 單一 instance → 死結
  • 有環 + 多 instance → 不一定死結
🛡️ 處理死結四方法
  1. Prevention：破壞四條件之一
  2. Avoidance：銀行家演算法
  3. Detection + Recovery
  4. Ignore：UNIX/Windows 採用
🔧 死結預防（破壞各條件）
破壞方法
Hold & Wait一開始請求全部 / 請求前先釋放所有 → 利用率低、飢餓
No Preemption請求不到就釋放所有持有（適合記憶體類）
Circular Wait資源排序 F:R→N，只能遞增順序請求
🏦 死結避免：Safe / Unsafe 狀態 2015/2016 必考觀念
⚠️ 最常考的觀念陷阱

Safe state ⊂ 非死結　｜　Deadlock ⊂ Unsafe　｜　但 Unsafe 不一定死結！

不安全只表示「無法保證避免死結」。若行程提早釋放資源或不索取到最大需求，仍可能順利完成。所以 unsafe MAY BUT NOT NECESSARILY lead to deadlock。

📑 分頁 (Paging) + 頁表大小計算 每年必考

邏輯位址 = page number (p) | page offset (d)

★ 頁表大小公式
偏移位元 = log₂(頁大小) 頁號位元 = 邏輯位址位元 − 偏移位元 頁數 = 2^(頁號位元) 頁表大小 = 頁數 × 每筆 entry 大小

實體記憶體大小不影響頁表筆數！只看邏輯位址 + 頁大小。

分頁無外部碎裂，但有內部碎裂（平均半頁/行程）。

⚡ TLB（轉譯後備緩衝區）
  • 頁表在主記憶體 → PTBR 指向 → 兩次存取（慢）
  • TLB 快取 (頁號→frame號)，64~1024 筆
  • 有效存取時間 = hit×(TLB+mem) + miss×(TLB+2mem)
  • 例：80%命中,TLB20,mem100 → 0.8×120+0.2×220 = 140ns
🗂️ 頁表結構 & 分段
  • Hierarchical（多層）：頁表也分頁；64-bit 不適用
  • Hashed：虛擬頁號雜湊
  • Inverted：全系統一張，省記憶體但搜尋慢、難共享
  • Segmentation：<segment#, offset>，有外部碎裂
🧩 連續配置 & 碎裂

配置策略：First-fit（最快）/ Best-fit（剩最小碎片）/ Worst-fit（最差）

  • External fragmentation：總空間夠但不連續（50% 規則）→ Compaction（須執行時動態重定位）
  • Internal fragmentation：固定分割配置略大於需求
🟣 Chapter 9 — Virtual Memory Management
📥 需求分頁 (Demand Paging) & Page Fault 流程 2013/15/16 考
  1. 查內部表：合法 or 非法存取
  2. 非法 → 終止行程
  3. 合法但未載入 → 找 free frame（沒有則頁面置換）
  4. 檢查 victim modify (dirty) bit：改過才寫回磁碟
  5. 讀入該頁，更新頁表（valid bit）
  6. 重新執行被中斷的指令
有效存取時間 (EAT)
EAT = (1 − p) × ma + p × page_fault_time

p = page fault 率。例：ma=200ns, fault=8ms → EAT = 200 + 7,999,800×p（p 須極小）

🔄 頁面置換演算法 每年必考計算
演算法規則重點
FIFO換最舊簡單；有 Belady's anomaly
Optimal換未來最久不用最低 fault，需未來知識（不可實作）
LRU換過去最久沒用OPT 近似；stack 演算法無 Belady's anomaly

LRU 近似：Reference bit、Second-chance (clock)、Enhanced second-chance ((ref,modify) 四類)。
